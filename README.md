# ivuorinen/homebrew-tap

A Homebrew tap for ivuorinen's custom formulae with automated documentation and dark mode support.

## Quick Start

```bash
# Add the tap
brew tap ivuorinen/homebrew-tap

# Install a formula
brew install <formula-name>

# List available formulae
brew search ivuorinen/homebrew-tap/
```

## Documentation

Visit [https://ivuorinen.net/homebrew-tap/](https://ivuorinen.net/homebrew-tap/) for complete documentation with:
- Installation instructions for each formula
- Dependencies and version information
- Source links and SHA256 checksums
- Dark mode support with system preference detection

## Automated formula sync

Formulae are generated from upstream GitHub releases — the tap **pulls**, the
tools don't push. The list of tracked repos lives in
[`formula-sources.json`](formula-sources.json):

```json
[
  { "repo": "ivuorinen/a", "desc": "Optional override for the audit-safe description" },
  { "repo": "ivuorinen/gh-history" }
]
```

Each entry needs only `repo`. Optional overrides: `desc` (when the auto-derived
one reads badly), `license`, `bin` (binary name inside the archive), and `test`
(the `test do` command).

[`scripts/sync_formulae.rb`](scripts/sync_formulae.rb) asks the GitHub API (via
`gh`) for **every release** of each repo, matches the prebuilt binary assets to
macOS/Linux × arm64/x86_64, and writes one formula per version: the repo's
latest release (GitHub's `releases/latest`, so never a draft or prerelease)
becomes `Formula/<x>/<name>.rb`, and every published release (including the
latest) also becomes a `keg_only`, versioned `Formula/<x>/<name>@<version>.rb`
you can install with `brew install <name>@<version>`. Older releases without
matching prebuilt binaries are skipped; a latest release without them fails
that repo. `sha256` comes straight from the API's per-asset `digest`, so nothing
is downloaded. A versioned formula whose release is no longer published
(deleted, or made a draft or prerelease again) is deleted; hand-written
formulae, which lack the "generated by" header, are never touched. Run it
locally with:

```bash
mise run sync    # needs gh authenticated (gh auth login)
```

The [`Sync formulae from releases`](.github/workflows/sync-formulae.yml) workflow
runs it daily (and on demand), validates the result in-job with `brew test-bot`
(via the shared [`.github/actions/ci`](.github/actions/ci/action.yml) composite
action, reused by CI), and opens a PR when anything changed. A repo that fails
to sync keeps its existing formulae and does not block the others: the PR still
opens for the repos that synced, and the run then fails, listing the failures
in its job summary.

## Contributing

Most formulae are managed by the sync above — add the repo to
`formula-sources.json` rather than hand-writing a formula. For a one-off manual
formula:

1. Fork this repository
2. Create a new formula in the `Formula/` directory following the [Homebrew Formula Cookbook](https://docs.brew.sh/Formula-Cookbook)
3. Submit a pull request

The CI will automatically validate your formula and update the documentation site.

## Development

This tap uses a custom Ruby-based static site generator. Its tools come from
[mise](https://mise.jdx.dev), pinned in `mise.toml`, the single source of tool
versions for local work and CI: Ruby, Node.js for terser's JS minification,
the gh CLI for the sync, and prek for the pre-commit hooks. The gems in
`Gemfile` install into `vendor/bundle`.

### Quick Start

For new contributors or first-time setup:

```bash
mise install      # Install Ruby, Node.js, gh and prek at the pinned versions
mise run setup    # Check the project structure and install the gems
mise run serve    # Build the site, serve it, and rebuild on changes
```

### Commands

Every command is a mise task, a script in `.mise/tasks/`. `mise tasks` lists
them with descriptions; `mise run <task> --help` shows a task's options.

```bash
mise run build    # Build the documentation site
mise run serve    # Development server on http://localhost:4000 (aliases: dev, watch)
mise run parse    # Parse formulae and generate JSON data only
mise run clean    # Clean all generated files
```

**Development workflow:**
```bash
mise run setup    # Initial setup: check project structure, install Ruby dependencies
mise run test     # Syntax-check the scripts and run the offline tests
mise run check    # Check project structure
mise run install  # Install Ruby dependencies
mise run info     # Show project information
```

**Server options:**
```bash
mise run serve --port 3000                 # Use port 3000
mise run serve --host 0.0.0.0              # Bind to all interfaces
mise run serve --port 8080 --host 0.0.0.0  # Custom port and host
```

**Homebrew-specific tasks:**
```bash
mise run tap-test               # Audit the tap as CI does (brew test-bot)
mise run tap-install            # Install this tap locally
mise run formula-new tool-name  # Create new formula template
```

**Production and testing:**
```bash
mise run build-production  # Clean build for production deployment
mise run version           # Show version information
```

A task fails as soon as any of its commands fails.

**File Watching and Auto-Rebuild:**

The development server (`mise run serve`) polls the source files once a second and
rebuilds after a one-second debounce. Each rebuild runs the parse and build
scripts as fresh processes, so edits to the scripts take effect without a
restart. Generated output under `docs/` is not watched.

Files monitored for changes:
- `Formula/**/*.rb` - Homebrew formula files
- `theme/**/*` - Templates, CSS, JS and assets
- `scripts/parse_formulas.rb`, `scripts/build_site.rb`, `scripts/asset_processor.rb`, `scripts/time_formatter.rb` - Build scripts

### How It Works

The documentation system consists of three main components:

1. **Formula Parser** - Safely extracts metadata from `.rb` files using regex patterns (no code evaluation)
2. **Site Builder** - Generates static HTML from ERB templates using the parsed data
3. **Development Server** - Serves the site locally with auto-rebuild on file changes

### Project Structure

```
docs/
├── _data/                  # Generated JSON data
├── assets/                 # Copied static assets (fonts, images, etc.)
├── formula/                # Individual formula pages (generated)
├── index.html              # Homepage (generated)
└── formulae.html           # Formula listing (generated)
theme/
├── assets/                 # Original assets: fonts, images, etc.
├── _command_input.html.erb # Input command snippet partial
├── _footer.html.erb        # Footer partial
├── _formula_card.html.erb  # Formula card partial
├── _head.html.erb          # HTML head partial
├── _header.html.erb        # Header partial
├── _nav.html.erb           # Navigation partial
├── _nothing_here.html.erb  # "No formulae found" partial
├── index.html.erb          # Homepage template
├── formulae.html.erb       # Formula listing template
├── formula.html.erb        # Individual formula template
├── style.css               # Tailwind input: directives, fonts, base styles
└── main.js                 # Site functionality: search, dark mode toggle, etc.
Formula/
└── <letter>/<name>.rb      # Homebrew formula files (generated by the sync)
scripts/
├── sync_formulae.rb        # GitHub releases -> Formula/ (mise run sync)
├── parse_formulas.rb       # Formula/ -> docs/_data/formulae.json (mise run parse)
├── build_site.rb           # formulae.json + theme/ -> docs/ (mise run build)
├── asset_processor.rb      # Tailwind CSS compile, JS minify, asset copy
├── time_formatter.rb       # Date formatting for the templates
├── serve.rb                # Development server (mise run serve)
├── file_watcher.rb         # Change polling for the development server
└── test_sync_formulae.rb   # Offline tests (mise run test)
formula-sources.json        # Repos the sync tracks
mise.toml                   # Tool versions: Ruby, Node.js, gh, prek
.mise/tasks/                # Build commands, one script per task
README.md                   # This documentation
Gemfile                     # Ruby dependencies
```

### Features

- ✅ Static output: CSS compiled at build time, no runtime CDN scripts
- ✅ Fast builds with auto-reload development server
- ✅ Dark mode with system preference detection
- ✅ Responsive design with accessibility support
- ✅ GitHub Pages compatible output
- ✅ Automatic deployment via GitHub Actions

### Customization

Templates can be customized by editing files in the `theme/` directory:
- `index.html.erb` - Homepage template
- `formulae.html.erb` - Formula listing page
- `formula.html.erb` - Individual formula page template
- `style.css` - Stylesheets and theming
- `main.js` - JavaScript functionality
