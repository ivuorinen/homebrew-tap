# Architecture Profile
Generated: 2026-10-16

## Detected Patterns

### Pipe and Filter — Medium confidence
Evidence:
- Three stages, each a standalone script that reads one artifact and writes the next:
  1. `scripts/sync_formulae.rb`: GitHub releases API (via `gh`) → `Formula/<x>/<name>[@<ver>].rb`
  2. `scripts/parse_formulas.rb`: `Formula/**/*.rb` (regex, no evaluation) → `docs/_data/formulae.json`
  3. `scripts/build_site.rb`: `docs/_data/formulae.json` + `theme/*.erb` → `docs/**/*.html`, `style.css`, `main.js`
- Stages share no Ruby code: build_site.rb requires only `time_formatter` and `asset_processor`, and parse_formulas.rb requires only stdlib. The hand-off is the file on disk.
- The orchestrators (`Makefile` build/parse, `serve.rb`, CI workflows) run the stages in order; no stage calls another's internals.
- Medium, not High: there is no `pipeline/` or `filters/` directory or naming. The pattern is inferred from data flow.

### Plugin / Extension, MVC, Layered and the others — not detected
- No core-plus-registry, no models/views/controllers split, no layer directories. ERB templates under `theme/` are presentation for stage 3 only.

## Detected Combination
None. A single pattern: Pipe and Filter with file-based hand-off.

## Inferred Structural Rules
- Each stage consumes only the previous stage's output artifact, never its source code or in-memory state.
- The artifact formats are the contracts between stages:
  - Formula file → parser: the `# released: <ISO8601>` comment and the tag-bearing asset URL (the version source) that sync_formulae.rb writes and parse_formulas.rb's PATTERNS read.
  - `formulae.json` → builder: the keys `name`, `description`, `version`, `url`, `homepage`, `license`, `sha256`, `dependencies`, `released_at`, `last_modified`, `file_path`, plus top-level `tap_name`, `generated_at`, `formulae_count`, `formulae`.
- A contract change must update producer and consumer together, and a test should exercise both sides of it rather than a copy of either.
- Generated artifacts (`Formula/` from stage 1, `docs/` output from stages 2-3) are not hand-edited. Formula files state "generated by scripts/sync_formulae.rb; do not edit by hand".

## Ambiguities & Contradictions
- The formula-file contract is duplicated rather than shared. test_sync_formulae.rb re-implements parse_formulas.rb's `released:` and URL-version regexes instead of calling FormulaParser, so the test can pass after the parser changes (see the tests finding).
- `Makefile formula-new` and README "For a one-off manual formula" let hand-written formulae into `Formula/`, alongside the generated ones. The parser handles both, so this is a second producer for stage 2, not a violation.
